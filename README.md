# MLOPS-26: домашние работы 3–5

## ДЗ 5 — первый LoRA-ран

Два полных запуска `Qwen/Qwen3-0.6B` на собственных тензорах ДЗ4:
LoRA r=8 на всех 28 слоях и вариант без адаптеров на первых 14 слоях.
В каждом запуске 192 шага, 1536 train-примеров и 21 замер на всех 188 val-примерах.
На Ryzen 5 5500U (CPU, float32, 6 потоков) оба запуска заняли 6 ч 32 мин.

| Вариант | Обучаемые параметры | Val loss до → после |
|---|---:|---:|
| all_layers | 5 046 272 | 1.767276 → 0.416914 |
| freeze14 | 2 523 136 | 1.767276 → 0.433380 |

Подробные результаты и ограничения: [отчёт ДЗ5](docs/hw5_results.md),
[кривые](docs/curves.png), [пять фиксированных вопросов](docs/compare.md),
[пять исправленных дефектов](docs/defects.md#дз-5-первый-lora-ран-на-собственном-датасете).
Снижение loss не гарантирует фактическую точность: адаптер всё ещё выдумывает
географические факты; эти ошибки показаны в отчёте.

### Проверить уже обученные артефакты

Из папки этого репозитория:

```powershell
uv sync
uv run dvc pull
make check
```

На текущем компьютере файлы уже находятся на месте, поэтому `dvc pull` можно
пропустить. `make check` не повторяет полное обучение: проверяет сохранённые
результаты, загрузку адаптера без сети и два коротких прогона по три шага.
На Windows используется Git Bash из Git for Windows, а не WSL; вывод UTF-8.
Журнал проверки: `runs/check.log`, итог: `runs/check.status.json`.
Курсный `tests/check.sh` не изменён, его SHA-256 начинается с `06a02208c1f0`.

### Выполнить обучение заново

```powershell
uv sync
uv run dvc pull
make train
make compare
make check
make report
```

`make train` действительно обучает оба варианта заново и занимает несколько
часов на CPU. Для независимого от окна редактора запуска на Windows есть
`scripts/run-training.ps1`; состояние и журнал — `runs/status.json` и
`runs/training.log`. Перед запуском подключите питание. `make clean` удаляет
только результаты ДЗ5, но не исходные данные ДЗ3/4.

Данные, адаптеры, токенизатор и JSON-метрики хранятся **в DVC, не в GitHub**.
Настроенный remote локальный: `D:/mlops/dz5/dvc_remote` (относительный адрес
`../../dvc_remote` в `.dvc/config`). На другом компьютере нужно передать этот
каталог или настроить доступный remote: `uv run dvc remote modify local url <путь>`.
Для offline-проверки веса базовой Qwen также должны быть в локальном HF-кеше;
на новом компьютере предварительно загрузите модель с доступом к сети.
`dvc.lock` фиксирует уже вычисленные артефакты; при завершении работы использован
`dvc commit`, а не повторный многочасовой `dvc repro`. Проверено, что
`dvc status` не обнаруживает изменений и `dvc push` сохраняет артефакты в remote.

## ДЗ 3 — собственный датасет

Воспроизводимый DVC-пайплайн собственного датасета **GeoNames City Facts RU**:

```text
GeoNames → collect → clean → diversity → split → contamination check
```

Исходные структурированные факты берутся из закреплённого в `uv.lock` пакета
`geonamescache==3.0.2` и переразмечаются в русскоязычный chat JSONL. Данные не
хранятся в Git: DVC использует локальный remote, описанный выше.

## Запуск

```bash
uv sync
make repro
make check-hw3
```

Управление версиями и проверки:

```bash
make v1             # 80 стран, 320 городов, 1280 сырых примеров
make v2             # 100 стран, 500 городов, 2000 сырых примеров
make diff           # разница метрик workspace и Git
make diversity      # гейт разнообразия
make contamination  # пересечения train/test
make dag            # граф DVC
```

Для явного сравнения зафиксированных версий:

```bash
uv run dvc metrics diff hw3-v1 hw3-v2
```

## ДЗ 4 — токенизация для обучения

Стадия `tokenize` продолжает граф DVC после `split`. Вход — собственные
`data/train.jsonl` и `data/val.jsonl` из ДЗ 3; для самой токенизации модель
не загружается, используется только `Qwen/Qwen3-0.6B` tokenizer.

```bash
uv sync
make tokenize       # тензоры, метрики и генерируемый отчёт
# Самопроверка ДЗ4 сохранена в исходной папке dz4; здесь make check проверяет ДЗ5.
uv run dvc repro tokenize
```

На Windows цель `check` запускает Git Bash, а не WSL. Результат:
1536 train и 188 val примеров, `max_seq_len = 144`, обрезка 0%,
левый динамический паддинг, 45743 обучаемых токена из 136977 в train.
Packing выключен, поскольку блочная attention-маска здесь не реализована.

Числа и прогноз времени: [отчёт tokenize](docs/tokenize_report.md),
`metrics/tokenize.json` (после `dvc pull`). Исправления четырёх дефектов подробно
описаны в разделе ДЗ 4 [разбора дефектов](docs/defects.md).

Токенизированные файлы находятся в `data/tokenized/` под DVC; Git хранит
код, параметры, `dvc.lock` и отчёт, но не данные, тензоры или JSON-метрики.
